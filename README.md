# PowerShare · 功耗与显示器工具

一个 Windows 小工具：**看实时功耗、控制显示器、诊断「一跑重载就死机」**。

双击即用，不需要安装、不需要管理员权限、不写注册表、不建开机启动。

> 起因很简单：一台笔记本在游戏满载 5 分钟后必定硬冻结，无蓝屏、无转储、无硬件错误日志。
> 为了找出到底是散热、供电、还是接触问题，写了几行代码开始记录功耗；
> 后来记录越来越多，就成了这个工具。它**不修硬件**，只负责把证据摆出来。

## 快速开始

### 方式一：直接运行（推荐给普通用户）

1. 到 [Releases](../../releases) 下载 `PowerShare-1.0.0.exe`（附带中文说明 `USAGE-zh.txt`）
2. 双击运行
3. 首次打开会看到「Windows 已保护你的电脑」——点 **更多信息 → 仍要运行**（程序未做代码签名）

### 方式二：源码运行

```bash
# 需要 Python 3.9+（仅用标准库，无第三方依赖）
pythonw share_edition.pyw
```

三个文件放在同一目录即可：`share_edition.pyw`、`display_ctl.py`、`power_fault_view.py`。

数据目录固定在 `%LOCALAPPDATA%\PowerShare\`，与程序位置无关；删掉这个目录等于清空所有记录。

## 如果碰上「一跑重载就死机」

这几步不花钱，比装任何软件都准：

1. **满载 20 分钟后摸电源插头（DC 头）**
   明显发烫 → 接触电阻大，先清洁或更换 DC 头 / 电源线

2. **满载时看软件里的「电池」一行**
   出现 `放电 xxW` → 适配器已到极限，开始向电池借电
   一直是 `0W` → 适配器还有余量，问题在机器内部

3. **清洁 DC 头 + 机器端插孔后再测**
   原来 5 分钟崩、清洁后能撑 15 分钟以上 → 就是接触问题

4. **看诊断页的崩溃时刻分布**
   全部集中在高负载时段、且日志里没有任何「电源断连」记录
   → 多半是供电链路（适配器 / 电池 / 主板供电相），不是软件

做完这四步再去维修店，就能明确告诉师傅查什么，省掉「先重焊 CPU」这种最贵的试错。

## 关于「保温」功能

焊点失效的主要原因是**热循环**（反复热胀冷缩），而不是单纯的高温。
所以让机器保持温热、减小冷机启动时的温差，这个思路本身是成立的。

但代价是真实的：

- 常年多耗 10–20W 电
- 笔记本长期处于偏高温度（对电池寿命不利）
- 风扇持续运转，进灰更快

而且它**只对「冷机第一次启动就死机、热起来反而稳定」这一类机器**有意义。
**热机满载才崩的情况，保温帮不上忙**——那种情况请先查供电与散热。

因此它默认关闭，需要手动确认才开启；使用电池或显卡超过 80℃ 时会自动暂停。

## 实现说明

- **纯标准库**：只用 `ctypes` 调 Win32，不依赖 `pywin32`、`wmi`、`psutil`
- **GPU 功耗**：`nvidia-smi --query-gpu=power.draw`
- **电池充放**：`CallNtPowerInformation(SystemBatteryState)`
- **显示器断开/连接**：`SetDisplayConfig` 操作 `DISPLAYCONFIG_PATH`
  （注意：断开后 Windows 会清除该屏的模式，重连必须用
  `DISPLAYCONFIG_DEVICE_INFO_GET_TARGET_PREFERRED_MODE` 重建 source/target mode，
  只改 ACTIVE 标志是连不回来的）
- **显示器关背光**：DDC/CI `VCP 0xD6`
- **崩溃统计**：`wevtutil` 读 `Event 41`（异常重启）与 `Kernel-Power 105/566`（电源断连）

### 构建

```bash
pip install pyinstaller
pyinstaller --onefile --windowed --name PowerShare ^
  --hidden-import display_ctl --hidden-import power_fault_view ^
  share_edition.pyw
```
